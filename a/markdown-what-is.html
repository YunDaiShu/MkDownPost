Markdown 是什么：定义、起源与设计哲学

概念 · 历史 · 7 分钟 · 2026-10-16

一句话定义

Markdown 是一种轻量级标记语言：用纯文本写作，通过少量符号表达结构（标题、列表、引用、代码等），最终可以转换成 HTML 发布。

它的目标是可读性优先——即使不渲染，原始文本也应该像一封排版清楚的邮件，而不是一堆标签。

# 这是标题
- 这是列表
> 这是引用

对比 HTML：

<h1>这是标题</h1>
<ul><li>这是列表</li></ul>
<blockquote>这是引用</blockquote>

两者表达同样的结构，但 Markdown 的原文在任何文本编辑器里都读得下去。

它从哪来（2004）

  • John Gruber（Daring Fireball 作者）在 2004 年发布了 Markdown 的第一版语法说明与转换脚本（Perl 实现）。
  • Aaron Swartz 参与了早期设计讨论，并推动了它在社区中的传播。他 14 岁参与 RSS 1.0 规范，后参与 Reddit，2013 年去世。
  • 设计初衷很简单：让写博客的人不必手写 HTML，同时让源码保持人类可读。

一个常被忽略的细节：Markdown 从诞生起就不是"标准"，它是一份语法说明 + 参考实现。这为后来的方言问题埋下伏笔。

为什么它活下来了

原因 说明
纯文本 不绑定软件，20 年后仍能用记事本打开
极简 常用语法一只手数得完，5 分钟能上手
兼容 HTML Markdown 里可以直接嵌 HTML，不牺牲能力上限
跨平台 同一份 .md 能上 GitHub、进博客、进公众号、转 PDF
版本可控 纯文本天然适合 Git diff，改一个字只有一行变化

它适合什么、不适合什么

适合

  • 技术文档、README、API 说明
  • 博客、公众号、小黑盒、TapTap 这类以长文为主的平台
  • 需要版本管理的内容（配合 Git）
  • 需要"一份内容多处发布"的场景

不适合

  • 需要精确像素排版的印刷品（用 InDesign / Word）
  • 复杂表格与合并单元格（Markdown 表格是"一行一记录"的简化模型）
  • 需要强交互的页面（那是 HTML/CSS/JS 的领域）
  • 多人实时协同写作（需要专门的协同编辑系统）

Markdown 与 HTML 的关系

Markdown 不是 HTML 的替代品，而是它的简写层：

  1. 你写 Markdown；
  2. 解析器把它转成 HTML；
  3. 浏览器渲染 HTML。

所以 Markdown 的能力上限受限于"解析器支持到哪"。这也解释了为什么：

  • 有的平台支持表格，有的不支持；
  • 有的支持任务列表 - [x]，有的不支持；
  • 同一份 .md 在 GitHub 和公众号里长得不一样。

常见方言

方言 出处 主要扩展
原始 Markdown John Gruber, 2004 基础语法
CommonMark 社区标准化（2014 起） 明确边界情况，统一解析行为
GFM（GitHub Flavored Markdown） GitHub 表格、任务列表、删除线、自动链接
各平台方言 公众号、掘金、CSDN 等 各自的白名单/扩展

本站采用 GFM 语法集（表格、任务列表、删除线、自动链接），这是目前最通用的子集。

一段历史的意义

Markdown 能被广泛采用，不是因为语法多优雅，而是因为它把"写"和"排版"解耦了：

  • 写作时只关心结构与内容；
  • 排版交给主题、CSS、目标平台；
  • 需要换风格时，内容一个字都不用改。

这也是本站的设计前提：你写 Markdown，排版交给主题与导出适配器。

附：10 个常被误解的点

  1. Markdown 不是所见即所得：你看到的是符号，不是最终排版。
  2. 它不是标准：原始版本只有说明文档，标准来自后来的 CommonMark。
  3. 它不是 HTML 的替代：它是 HTML 的简写层，最终仍转成 HTML。
  4. 它不能精确定位：没有"第 3 行缩进 2 厘米"这种概念。
  5. 它不管分页：PDF 分页是导出器算的。
  6. 它不是编程语言：没有变量、循环、条件。
  7. 扩展不是标配：表格是 GFM 扩展，不是原始语法。
  8. 缩进敏感：列表与代码块都靠缩进判断层级。
  9. 中文排版要额外处理：标点、字距、换行规则都不在语法里。
  10. 它只保证结构：好不好看取决于主题与目标平台。

附：为什么技术圈几乎全员用它

  • Git 友好：纯文本 diff 精确到字符，评审能看清每一处改动。
  • 工具链齐全：编辑器、静态站生成器、文档平台默认支持。
  • 迁移成本低：二十年后仍能用记事本打开、用脚本转换。
  • 写作不分心：没有工具栏要调，专注内容。

一个现实观察：越是长期维护的文档，越倾向 Markdown；越是需要精确排版的交付物，越倾向 Word/PDF。

附：给非技术写作者的三条建议

  1. 先记 5 个语法（标题、加粗、列表、引用、链接），够写八成稿子。
  2. 别背全表，用速查表，遇到再查。
  3. 写完先看预览，结构问题一眼就能发现。
