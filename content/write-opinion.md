# 写观点：结论先行，理由跟上

技术文章也需要观点，否则只是资料搬运。

## 结构

```text
结论（一句话）
  ↓
三条理由（每条一句加一个例子）
  ↓
反方观点与回应
  ↓
适用边界（什么情况下不成立）
```

## 为什么结论要先行

读者的注意力在前三行。把结论放最后，等于赌他会读完。

## 三条理由的质量

| 质量 | 表现 |
| --- | --- |
| 强 | 有数据、有对比、有具体场景 |
| 中 | 有逻辑推演，无数据 |
| 弱 | 我觉得、大家都这么说 |

## 一定要写边界

没有边界的观点不可信。至少写一句：这套做法在什么情况下不适用。

## 反方观点怎么写

```markdown
有人会说：这样做太麻烦。确实，如果一个月只写一篇，
手动排版比配主题更快。但一旦固定产出，模板化的收益就出来了。
```

## 小结

观点加边界，才是专业表达。只给结论不给边界，是喊口号。
