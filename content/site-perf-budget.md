# 性能预算：首屏该在多少毫秒内出内容

优化要有目标，否则会陷入无止境的折腾。

## 本站的三条预算

| 指标 | 目标 |
| --- | --- |
| 首帧内容 | 1 秒内出现编辑器与骨架 |
| 可交互 | 1.2 秒内可以打字 |
| 渲染完成 | 2 秒内预览出现真实内容 |

## 做法

1. **分步渲染**：先出骨架与输入框，预览延后
2. **按需加载**：渲染器、Markdown 引擎、平台适配器都不进首屏
3. **样式合并**：10 个样式表合成 1 个请求
4. **本地依赖**：不使用外部 CDN，避免额外 DNS 与连接

## 实测（同一台机器）

| 阶段 | 首帧 |
| --- | --- |
| 优化前 | 约 2.1 秒 |
| 分步渲染后 | 约 1.0 秒 |
| 按需加载后 | 约 1.0 秒（资源顺序改变） |
| 样式合并后 | 约 0.77 秒 |

## 不要做的事

- 为了"看起来快"而隐藏加载过程：用户会更困惑
- 一次性加载所有依赖：首屏被拖慢
- 引入大体积框架：收益不足

## 小结

性能预算的作用是**让取舍有依据**：知道首屏该多快，就知道什么该延后。
