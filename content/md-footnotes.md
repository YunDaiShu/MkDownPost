# 脚注：语法、平台差异与替代方案

脚注适合放"不影响主线、但需要交代"的信息：出处、补充说明、延伸阅读。

## 语法

```markdown
正文里放一个标记[^1]，继续写。

[^1]: 这里是脚注内容，可以写一句话也可以写一段。
```

命名也可以用自己的标签：

```markdown
另一个标记[^note]

[^note]: 内容与编号无关。
```

## 支持情况

| 平台 | 是否支持 | 表现 |
| --- | --- | --- |
| GitHub | 支持 | 文末生成脚注区，可点击跳转 |
| 本站预览 | 支持 | 文末列表 |
| 公众号 | 不支持 | 标记与定义都会原样显示 |
| 小黑盒、TapTap | 不支持 | 同上 |

## 公众号里的替代写法

既然不解析，就别硬用。三种替代：

1. **文末统一写"注"**：正文标（注 1），文末列注 1、注 2
2. **用引用块**：把补充说明放在正文下方
3. **直接删**：多数补充说明删掉也不影响理解

```markdown
正文提到某个数据（见文末注 1）。

> 注 1：数据来源为某年公开报告，样本量 1200。
```

## 什么时候真该用脚注

- 学术味较重的引用
- 需要交代来源链接的长文
- 括号会打断句子节奏的补充说明

## 什么时候不该用

- 只是想多写两句话（直接写）
- 内容对理解主线重要（该进正文）
- 目标平台是公众号（会被原样显示，很丑）

## 小结

脚注是"体面的补充说明"。跨平台写作时，先看目标平台是否支持；不支持就用引用块或文末注替代。
