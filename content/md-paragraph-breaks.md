# 段落、换行与空白：最容易被忽略的规则

九成的排版莫名其妙问题，源头都是空行。

## 三条基本事实

1. **空行分段**：两个段落之间必须有一个空行
2. **单回车不分段**：多数解析器把单回车当成空格
3. **行尾两个空格加回车**：段内换行

## 三种换行方式对比

| 写法 | 渲染结果 | 适用场景 |
| --- | --- | --- |
| 空一行 | 新段落，有段间距 | 最常用 |
| 行尾两个空格加回车 | 段内换行，无段间距 | 诗歌、地址、签名 |
| 行尾反斜杠加回车 | 段内换行 | 兼容写法 |
| 直接回车 | 视解析器而定 | 不可靠 |

## 为什么空行这么重要

~~~markdown
第一段
第二段（没有空行，可能被并成一段）

第一段

第二段（有空行，一定是两段）
~~~

块级元素（列表、代码块、引用、表格）前面**也要空行**，否则会粘进上一段。

## 首行缩进怎么办

Markdown 没有首行缩进概念。三种做法：

1. 用全角空格（不推荐，复制到别处会乱）
2. 用 CSS 的 text-indent，但公众号不认外链样式
3. **不缩进**：现代中文排版本就倾向段间留白代替首行缩进

本站主题采用第 3 种：段间留白加行高，观感更干净。

## 三个坑

- 代码块内的空行会被保留，不影响结构
- 列表项之间的空行会产生宽松列表，间距变大
- 引用块内的空行如果没带引用符号，引用会被截断

## 自检清单

- [ ] 每个块级元素前有空行
- [ ] 没有单回车分段的段落
- [ ] 列表项之间风格统一
- [ ] 代码块首尾各有空行
