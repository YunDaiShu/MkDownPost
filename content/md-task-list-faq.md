# 任务列表：各平台表现与替代方案

任务列表是 GFM 扩展，不是原始语法，所以跨平台时最容易丢样式。

## 标准写法

```markdown
- [x] 已完成
- [ ] 未完成
- [ ] 进行中
```

## 各平台表现

| 平台 | 显示方框 | 可点击勾选 |
| --- | --- | --- |
| GitHub | 是 | 是（仅仓库内） |
| 公众号 | 否，退化为文字 | 否 |
| 小黑盒 | 否 | 否 |
| TapTap | 否 | 否 |
| 知乎、掘金 | 部分 | 否 |

## 降级方案

本站平台适配器会把任务列表转成可见字符：

```markdown
未勾选 → 空方框 未完成
已勾选 → 打勾方框 已完成
```

这样在公众号里也能看出打了勾和没打勾。

## 什么时候用任务列表

- 教程里的步骤清单（读者跟着勾）
- 发布前自检
- 项目进度（GitHub 仓库里最合适）

## 不适合的场景

- **公众号正文**：方框显示不出来，观感反而怪
- **需要强调顺序**：用有序列表
- **需要多列**：用表格

## 手写字符方案（全平台通用）

```markdown
- ☑ 已完成
- ☐ 未完成
- ◐ 进行中
```

这几个字符在任何平台都能显示，缺点是不可点击。

## 小结

任务列表在自己用的场景很爽，在发出去的场景几乎必然降级。写公众号时直接用字符方案更稳。
