# 不用登录的在线 Markdown 编辑器有哪些

"在线 Markdown 编辑器"这个说法包含三类完全不同的东西，混在一起比较没有意义。这篇先把它们分开，再讲怎么判断一个编辑器**是不是真的在本地处理你的文字**。

## 三类编辑器

| 类型 | 例子形态 | 数据在哪 |
|---|---|---|
| 云文档 | 有账号、有协作、有历史版本 | 厂商服务器 |
| 纯编辑器 | 打开就能写，关掉就没了 | 浏览器内存 |
| 排版导向 | 写完直接导出成某个平台的格式 | 取决于实现 |

你要写公众号，需要的是第三类；你要跟人协作，需要的是第一类。用错类型会觉得"怎么这么难用"。

## 为什么"不用登录"值得单独拿出来说

登录不是多一步操作那么简单，它意味着：

- 你的草稿存在别人的服务器上
- 你的邮箱或手机号进了对方数据库
- 服务下线，你的文章可能一起消失
- 断网就用不了

写一半的文章是最私人的东西之一。如果只是想让排版好看，没有必要把它交出去。

## 怎么验证它真的不上传

### 方法一：断网测试（最有效）

1. 打开编辑器页面（先让页面加载完）
2. 断开 WiFi 或拔网线
3. 粘贴一段文字，写几段

如果排版照常工作，说明渲染在浏览器里完成；如果按钮变灰、一直转圈、报网络错误，说明它依赖服务器。

### 方法二：看 Network 面板

按 F12 → Network → 贴一段文字 → 看有没有请求发出去。

- 只有静态资源（js/css/字体）→ 本地处理
- 有 POST 请求带着你的正文 → 上传了

### 方法三：看草稿存在哪

F12 → Application → Local Storage。如果草稿存在你这个域名的 localStorage 里，说明数据在本机浏览器；如果什么都找不到，说明它在服务器。

## 本地存储的两个风险，以及怎么应对

选本地处理，就要接受它的代价：

### 风险一：换浏览器就没了

localStorage 不跟账号走，换设备、换浏览器、清缓存都会丢。

**应对**：写完导出 Markdown 存到本地文件。任何编辑器都该有"导出"按钮，没有的话不要用。

### 风险二：无痕模式下会丢

无痕窗口关闭即清空。

**应对**：别在无痕窗口里写长文。

## 对比：三种方案的取舍

| 维度 | 云文档 | 本地编辑器 | 排版工具 |
|---|---|---|---|
| 内容是否上传 | 是 | 否 | 看实现 |
| 断网可用 | 否 | 是 | 看实现 |
| 多人协作 | 强 | 无 | 无 |
| 直接出公众号排版 | 弱 | 弱 | 强 |
| 数据归属 | 厂商 | 你 | 看实现 |
