# 解析器是怎么把 Markdown 变成 HTML 的

理解解析流程，很多"为什么这里不生效"就有答案了。

## 四个阶段

```text
源文本
  ↓ 分块（按空行切出块级元素）
块列表
  ↓ 行内解析（加粗、链接、代码）
带标记的树
  ↓ 生成 HTML 字符串
HTML
  ↓ 白名单过滤
安全 HTML
```

## 为什么"空行"这么关键

分块阶段靠空行判断"上一块结束"。没空行，两段会被当成一段，后面的行内解析自然全错。

## 为什么同一份 Markdown 表现不同

| 差异点 | 说明 |
| --- | --- |
| 方言 | CommonMark、GFM、各平台自研 |
| 扩展 | 表格、任务列表、脚注是否支持 |
| 后处理 | 生成 HTML 后是否再改写样式 |
| 白名单 | 允许哪些标签与属性 |

## 本站的管线

```text
Markdown
  → 解析（marked 优先，缺失时用内置解析器）
  → 清洗（标签与属性白名单）
  → 后处理（标题锚点、代码块工具条、图片懒加载）
  → 交互动效（公式、图表按需渲染）
```

## 小结

解析器不是黑盒：分块、行内、生成、过滤四步。知道卡在哪一步，排错就有方向。
