# 链接与图片：行内式、参考式与路径陷阱

链接写错是点不动，图片写错是裂图，两者都很难自查。

## 行内式

~~~markdown
[文字](https://example.com "可选标题")
![图片说明](https://example.com/a.png)
~~~

## 参考式（长文推荐）

~~~markdown
看 [官网][1] 与 [文档][2]。

[1]: https://example.com
[2]: https://example.com/docs
~~~

好处：链接集中在文末，改地址只改一处。

## 自动链接

~~~markdown
尖括号包住完整地址 → 自动变成链接
直接写 https 开头的地址 → GFM 下也可点
~~~

## 路径的三种写法

| 写法 | 例子 | 适用 |
| --- | --- | --- |
| 绝对地址 | https 开头的完整链接 | 跨平台发布首选 |
| 根相对 | 以斜杠开头 | 本站内部 |
| 文档相对 | assets/a.png | 仓库内、GitHub 预览 |

导出到公众号时，相对路径**全部会裂**——导出器会自动转成绝对地址，前提是你的域名可访问。

## 图片的五个要点

1. 写 alt：图裂时的兜底文字
2. 用 https：http 图片会被混合内容拦截
3. 控体积：单图小于 2MB
4. 首图 16 比 9：信息流裁切更完整
5. 别用 WebP：部分平台不转存

## 链接的四个坑

- 地址里有括号：维基条目这类地址会提前结束链接
- 标题里的引号：会干扰解析
- 公众号外链白名单：站外链接可能不可点
- 相对链接导出后失效：站内路由不要带进导出稿

## 自查清单

- [ ] 所有图片是 https 绝对地址
- [ ] 每张图有 alt
- [ ] 链接地址不含未转义括号
- [ ] 没有指向本机或内网地址的链接
