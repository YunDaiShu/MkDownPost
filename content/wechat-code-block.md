# 公众号里代码块怎么排版才不难看

公众号编辑器没有代码块。你粘进去的代码会变成普通正文：不缩进、不等宽、没有背景色，长行还会撑破手机屏幕。

写技术号的人几乎都被这件事折磨过。这篇把所有可行做法列清楚，包括每种做法的具体代价。

## 三种做法

| 做法 | 观感 | 读者能不能复制 | 维护成本 |
|---|---|---|---|
| 截图 | 最好看 | **不能** | 每次改代码都要重截 |
| 纯文本 + 等宽字体 | 一般 | 能 | 低 |
| 内联样式模拟代码块 | 好 | 能 | 低 |

我的结论：**能用内联样式就别截图**。截图看起来专业，但读者没法复制，也没法被搜索引擎读到。

## 做法一：内联样式模拟代码块

原理是把 `<pre>` 和 `<code>` 的样式全部写进 `style` 属性，因为公众号会丢掉 `<style>` 标签。

需要内联的最小样式集合：

```html
<pre style="margin:1em 0;padding:16px;background:#f6f8fa;
            border-radius:6px;overflow-x:auto;">
  <code style="font-family:SFMono-Regular,Consolas,Menlo,monospace;
               font-size:13px;line-height:1.7;color:#24292f;
               white-space:pre;">你的代码</code>
</pre>
```

五项缺一不可：`font-family`（等宽）、`white-space:pre`（不折叠空格）、`overflow-x:auto`（长行可滚）、背景色、`padding`。

## 做法二：控制行长，让代码不需要横向滚动

手机上正文宽度大约 **16 个汉字**，等宽字体下约 **30 到 34 个字符**。

超过这个长度的行，读者必须左右拖动才能看全——这在阅读体验上几乎是灾难。三个处理办法：

1. **拆行**：把长的函数调用按参数换行
2. **省略**：只贴关键几行，用 `// ...` 略过无关部分
3. **改示例**：换成更短的变量名和更简单的例子

第 3 条最有效，也最少人做。

## 做法三：语法高亮的取舍

真正的语法高亮需要把每个 token 包进 `<span>` 并染色。粘进公众号时，**大部分颜色会保留，少部分会被主题覆盖**。

实测下来比较稳的配色是：关键字一个色、字符串一个色、注释一个灰，其余全用正文色。颜色超过四种，粘进公众号后错乱的概率明显上升。

如果你用的主题在深色模式下有单独配色，记得检查一遍——公众号读者里深色模式占比不低。

## 一个容易忽略的细节：行号和复制

有些工具会给代码块加行号。行号在公众号里通常表现为一列数字 + 代码，读者复制时会**把行号一起复制走**，粘进编辑器就报错。

判断方法：在公众号后台预览，试着选中代码复制一次，看粘出来干不干净。

## 自测清单

- 等宽字体生效（数字和字母宽度一致）
- 背景色和正文有明显区分，但不刺眼
- 最长一行不超过 34 个字符
- 复制代码时不会带上行号
- 深色模式下仍然可读
- 缩进用空格而不是 Tab（Tab 在不同环境宽度不同）
