# Tab 与空格：看不见的排版杀手

缩进用 Tab 还是空格，决定了你的 Markdown 在别人机器上长什么样。

## 核心事实

- Markdown 的缩进语义是**空格数**（4 个空格等于一个代码块层级）
- Tab 的宽度由编辑器决定（2、4、8 都可能）
- 混用 Tab 与空格，缩进会错乱

## 建议

1. **统一用空格**
2. 列表缩进用 **2 个空格**
3. 代码块缩进用 **4 个空格**（相对父级）
4. 在编辑器里设置"Tab 转空格"

## 常见故障

| 现象 | 原因 |
| --- | --- |
| 代码块莫名出现 | 行首有 4 个空格 |
| 列表层级错乱 | Tab 与空格混用 |
| 表格列错位 | 单元格里有多余空格 |
| 引用被截断 | 空行漏了引用符号 |

## 行尾空格也有意义

行尾两个空格等于段内换行。所以：

- 编辑器里"自动删除行尾空格"会让换行失效
- 需要段内换行时，改用反斜杠加回车更稳

## 不可见字符

从网页复制来的文本可能带**零宽空格**，表现为"明明一样却解析不对"。处理办法：

- 粘贴到纯文本编辑器再复制
- 或者重新手打一遍那一行

## 小结

看不见的字符最容易制造玄学问题。统一空格、避免混用，能省掉一半排错时间。
