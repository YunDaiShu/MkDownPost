# 行内元素与块级元素：为什么排版会错位

理解这两类元素的区别，就理解了大部分 Markdown 排版问题。

## 两类元素

| 类型 | 例子 | 特点 |
| --- | --- | --- |
| 行内 | 加粗、斜体、行内代码、链接、图片 | 嵌在句子中间 |
| 块级 | 标题、段落、列表、引用、代码块、表格、分隔线 | 独占一行或一段 |

## 核心规则：块级不能塞进行内

```markdown
这是 **## 不是标题** 的写法（错误示范）
```

反过来，行内元素几乎可以放进任何块级容器：

```markdown
## 标题里的 **加粗**
- 列表项里的 **加粗**
> 引用里的 [链接](https://example.com)
```

## 块级可以嵌套块级

```markdown
- 列表
  > 里面的引用
  > 引用里的代码块要跟着缩进
```

嵌套时每一层都要跟着缩进或加引用符号。

## 为什么空行决定块级边界

解析器靠空行判断上一个块是否结束。所以：

- 列表前后没空行：粘进段落
- 代码块前后没空行：被当成行内
- 表格前后没空行：变成一段竖线文字

## 一张排错表

| 现象 | 大概率原因 |
| --- | --- |
| 整段文字变成同一个样式 | 行内标记没闭合 |
| 表格显示成竖线文字 | 前面缺空行 |
| 代码块没生效 | 用了行内代码而非围栏 |
| 列表挤成一行 | 项之间缺换行 |
| 引用吃掉后面正文 | 引用的空行没带引用符号 |

## 给自己一个检查习惯

写完一段后问一句：这一段是块级吗？前后有空行吗？这个小习惯能省掉大量返工。
