# 各平台图片规则实测对照（公众号 / 小黑盒 / TapTap / 知乎）

图片是跨平台发布最容易翻车的一环。这篇按平台拆开讲。

## 一、先记住三条通用结论

1. **绝对 URL 才安全**，相对路径在多数平台会裂
2. **宽度别超过版心**（超过会被压缩或裁切）
3. **一定要写 alt**，它是图裂时唯一可读的内容

## 二、公众号

| 项 | 规则 |
|---|---|
| 上传方式 | 粘贴时会**自动转存到微信 CDN** |
| 支持格式 | JPG / PNG / GIF（WebP 部分场景不支持） |
| 单图大小 | 建议 < 2MB，超过会压缩 |
| 首图比例 | 信息流裁切，**16:9 或 2.35:1 更稳** |
| 外链图片 | 部分域名会被拦（防盗链） |

**实操建议**

- 正文图宽度 677px（公众号版心）最稳
- 首图单独做一张 900×500
- 粘贴后**逐张确认**，转存失败会显示裂图

## 三、小黑盒

| 项 | 规则 |
|---|---|
| 图片展示 | 以卡片形式，比例影响裁切 |
| 支持的写法 | 标准 Markdown 图片语法可用 |
| 长图 | 会被压缩，建议切片 |
| 动图 | 支持 GIF，但体积敏感 |

**实操建议**

- 游戏截图建议 **16:9**
- 竖图（手机截图）建议拼成 2~3 张一行
- 图片下方加一行说明文字，读者更容易理解

## 四、TapTap

| 项 | 规则 |
|---|---|
| 图片 | 支持，但排版容器较窄 |
| 表格里的图 | 容易溢出，建议独立成段 |
| 截图清晰度 | 建议 2 倍图（Retina） |

**实操建议**

- 单图宽度不超过 640px
- 避免"图片 + 表格"混排
- 长截图切段，每段配一句说明

## 五、知乎

| 项 | 规则 |
|---|---|
| 图片 | 转存到知乎 CDN |
| 公式 | 不解析 LaTeX，会显示源码 |
| 代码块 | 限宽，过宽会横向滚动 |

**实操建议**

- 公式改用截图或纯文本描述
- 代码块控制在 60 字符宽以内
- 图片说明写在图下方单独一段

## 六、一张图能不能通用

| 平台 | 推荐宽度 | 比例 | 备注 |
|---|---|---|---|
| 公众号 | 677 | 16:9 | 首图 900×500 |
| 小黑盒 | 720 | 16:9 | 卡片裁切 |
| TapTap | 640 | 4:3 或 16:9 | 容器窄 |
| 知乎 | 690 | 自适应 | 限宽 |
| GitHub | 不限 | 不限 | 相对路径可用 |

**结论**：做一张 **1280×720（16:9）** 的图，在各平台都能用；只有 TapTap 需要留意容器宽度。

## 七、图裂的 6 个原因（按出现频率）

1. 用了相对路径（`assets/img/a.png`）
2. 图床开了防盗链（Referer 校验）
3. 图片被删或链接过期
4. 用了平台不支持的格式（WebP / AVIF）
5. HTTP 图片被 HTTPS 页面拦截（混合内容）
6. 图片体积过大，转存超时

## 八、图片的替代写法

当图片不可用时，至少让读者知道这里有什么：

@@@markdown
![界面截图：左侧编辑区，右侧实时预览](https://example.com/ui.png)

> 图注：如果图没显示，这是编辑器的双栏布局示意。
@@@

## 九、检查清单（发布前逐条打勾）

- [ ] 所有图片是 https 绝对地址
- [ ] 每张图都有 alt
- [ ] 首图是 16:9
- [ ] 单图 < 2MB
- [ ] 没有 WebP 格式
- [ ] 粘贴后逐张确认无裂图
- [ ] 手机预览确认无横向溢出
