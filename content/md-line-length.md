# 行长控制：为什么左右都别太满

行太长，眼睛会跳错行；行太短，节奏会碎。

## 经验值

| 场景 | 建议行长 |
| --- | --- |
| 中文正文 | 每行 30 到 40 字 |
| 英文正文 | 每行 60 到 75 字符 |
| 代码块 | 每行不超过 80 字符 |
| 表格 | 不超过 4 列 |

## 本站的做法

编辑器提供"行宽"两档：**标准 680 像素** 与 **宽 820 像素**。公众号正文版心约 677 像素，所以选标准最接近发布效果。

## 源文件里要不要手动断行

**不要**。源文件里的换行不等于渲染后的换行：

~~~markdown
这一行很短
这一行也很短
~~~

上面两行会被渲染成**同一段**。想让渲染后断行，要么空行分段，要么行尾两空格。

## 代码块的行长

~~~js
// 太长会被横向滚动，阅读体验差
const result = await fetchData({ page: 1, size: 20, sort: 'created_at', order: 'desc' });
~~~

改写成多行更友好：

~~~js
const result = await fetchData({
  page: 1,
  size: 20,
  sort: 'created_at'
});
~~~

## 小结

源文件随便写，渲染后的行长靠版心控制。代码块则要主动换行。
