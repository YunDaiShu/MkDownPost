# 写作工作流：从灵感到发布的一条流水线

工具不是重点，**流程**才是。这篇给一条可以直接照搬的流水线。

## 一、五个阶段

@@@text
1. 收集（Capture） → 2. 起草（Draft） → 3. 结构（Structure）
→ 4. 打磨（Polish） → 5. 发布（Publish）
@@@

每个阶段只做一件事，不要混着做。

## 二、收集：把想法先存下来

- 一个 `inbox.md`，想到什么写一行，不排版、不纠结
- 每周清一次：能成文的留下，其余删掉
- 判断标准：**这个话题我能写出 800 字吗**

## 三、起草：先写完，再写好

- 一次坐下只写一节，不求完整
- 允许烂句子，允许"这里以后补例子"
- 目标是**把骨架填满**，不是漂亮

## 四、结构：给读者路标

一篇 1500 字的文章，读者的耐心大概在第 3 屏耗尽。所以：

| 位置 | 要做什么 |
|---|---|
| 开头 3 行 | 说清"讲什么、对你有什么用" |
| 每 300~500 字 | 一个小标题 |
| 并列信息 | 用列表，不用长段 |
| 结尾 | 给下一步动作 |

## 五、打磨：删比写重要

三条硬规则：

1. **删掉"其实/基本上/我觉得"**这类填充词
2. **一段只讲一件事**，超过 5 行就拆
3. **每个论断后面跟一个具体例子或数字**

> 一个自检方法：朗读一遍，卡住的地方就是需要改的地方。

## 六、发布：一次写，多处发

@@@text
Markdown 原稿（唯一真相）
   ├─ 公众号：内联样式 HTML
   ├─ 小黑盒：适配（标题降级、图片 16:9）
   ├─ TapTap：适配（表格降级）
   ├─ 知乎：限宽
   └─ 归档：PDF / Word
@@@

要点：**永远从同一份 .md 出发**，不要在每个平台各改一版，否则后续维护会崩。

## 七、时间分配参考（1500 字文章）

| 阶段 | 时间 | 说明 |
|---|---|---|
| 收集 + 列提纲 | 15 分钟 | 想清楚要写哪几节 |
| 起草 | 40 分钟 | 一次写完，不停 |
| 结构整理 | 15 分钟 | 加小标题、拆段、加列表 |
| 配图 | 15 分钟 | 截图、标注 |
| 打磨 | 20 分钟 | 删废话、补例子 |
| 排版导出 | 10 分钟 | 选主题、导出粘贴 |
| 发布自检 | 10 分钟 | 手机预览、逐项检查 |

**总计约 2 小时**。其中"打磨"最容易被跳过，也最影响阅读体验。

## 八、工具选择的三条原则

1. **纯文本优先**：内容不被某个软件绑架
2. **本地优先**：断网也能写，草稿在自己手里
3. **导出能力**：能导出 HTML / PDF / 图片，才不会被平台锁死

## 九、常见坏习惯

| 坏习惯 | 后果 | 改法 |
|---|---|---|
| 一边写一边排版 | 注意力被切碎 | 内容完成后统一排版 |
| 每个平台各改一版 | 后续无法维护 | 只维护一份 .md |
| 不写小标题 | 读者跳读即放弃 | 每 300~500 字加一节 |
| 段落太长 | 手机端像砖墙 | 超过 5 行就拆 |
| 图片用相对路径 | 粘贴后全裂 | 一律绝对 URL |
| 不做发布自检 | 发出后才发现问题 | 用清单逐条打勾 |

## 十、一个可以立刻用的模板

@@@markdown
# 标题（说清"给谁、解决什么"）

一句话结论 / 这段的价值。

## 为什么这件事重要

- 现象
- 代价
- 数据或例子

## 怎么做

1. 第一步
2. 第二步
3. 第三步

## 常见坑

| 现象 | 原因 | 处理 |
|---|---|---|
| ... | ... | ... |

## 下一步

- 你可以立刻做的一件事
- 想深入可以看什么
@@@

把模板存成 `_template.md`，每次新建就复制一份。写够 10 篇，你会发现"写不出来"多数时候是**结构没搭好**，不是没内容。
