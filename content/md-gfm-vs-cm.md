# GFM 与 CommonMark 的差别：一张表说清

GFM 是 GitHub 在 CommonMark 上加的扩展集。

## 差异表

| 能力 | CommonMark | GFM |
| --- | --- | --- |
| 基础语法 | 支持 | 支持 |
| 表格 | 不定义 | 支持 |
| 任务列表 | 不定义 | 支持 |
| 删除线 | 不定义 | 支持 |
| 自动链接 | 仅尖括号形式 | 裸地址也可点 |
| 代码块语言 | 支持 | 支持且更宽松 |
| 脚注 | 不定义 | 部分实现支持 |

## 为什么要用 GFM 子集

- 表格与任务列表是技术写作刚需
- 主流平台（GitHub、掘金、知乎）基本兼容
- 降级路径清晰：不支持就转文本

## 写跨平台内容的三条纪律

1. 表格不超过 4 列
2. 任务列表准备字符替代
3. 脚注只在确定支持的平台用

## 小结

选 GFM 不是因为它"标准"，而是因为它**覆盖了最多平台的共同子集**。
